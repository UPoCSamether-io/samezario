# 最終成果発表に向けた改善 issue 一覧

目的：**「ついついもう1回やってしまう .io」**にすることと、**調布らしさが画面から伝わること**。
5分発表で「8月時点 → 最終版」の Before/After を見せられる差分を作る。

優先度：P0（必ずやる）＞ P1（できればやる）＞ P2（時間があれば）

---

## #0 [P0] スクリーンショット撮影スクリプト（基盤）

- `scripts/shots.mjs` を作る。playwright（既に devDependencies にある）で dev サーバを開き、主要画面を撮る。
- 撮る画面：タイトル／ロケ地選択（未解放の状態・全解放の状態）／サメ選択／ゲーム中（5マップ：調布駅・深大寺・多摩川・調布飛行場・つつじヶ丘仙川）／リザルト。
- ゲーム中は、開始直後と、開始から約8秒後の2枚。飛行場は気流が吹いている瞬間も1枚。
- 解放状態は localStorage の `samezario.save` を書き換えて作る（`src/progress.js` 参照）。
  全解放の例：`unlocked: ['chofu','jindaiji','tamagawa','airport','sengawa']`,
  `claimedSharks: ['cinema','dogu','tamagawa','jindaiji','kondo','airport','yokai']`
- 画面サイズは 1280×720（PC 横）と 844×390（スマホ横）の2種類。
- 出力：`docs/final/shots/<before|after>/<番号>-<画面名>-<pc|sp>.png`。同じ条件で何度でも撮り直せること。
- 対戦サーバ無しでも撮れるように（無ければソロに落ちる既存の動きでよい）。

## A. 遊び始めるまでの導線

### #1 [P0] 即リトライと「すぐ遊ぶ」
- リザルト画面で **Space / Enter** を押すと「もう一度撮る」（`#retry`）と同じ動きをする。ボタンにキー表示を小さく添える。
- タイトルに **「前回の設定ですぐ遊ぶ」** を足す。前回のロケ地・サメ・名前をセーブに残し、1クリックでゲーム開始。
  初回（前回の設定が無い）は出さない。
- 目標：死んでから次のプレイ開始まで **1秒以内・1操作**。

### #2 [P0] 「次に押すボタン」がわからない問題（ロケ地選択・サメ選択）
ユーザーテストで「どこを押せば次へ進むのかわからない」という声が多い。原因は、進むボタン（右上）が戻るボタン（左上）と
同じ大きさ・形で左右対称に置かれていて主役に見えないこと、視線の終点（右パネルの下・一覧の下）と逆の位置にあること、
ラベルが「サメ選択 →」という画面名で、押すと何が起きるかを言っていないこと。

- **ロケ地選択**：右の情報パネルの一番下に、パネル幅いっぱいの大きな主ボタンを常に見える位置で置く。
  - 解放済み：「このロケ地で撮影する →」
  - 未解放：同じ場所が「現地で写真を撮って解放」に変わる（既存の解放フローへ）
  - 解放済みエリアは地図上のダブルクリックでも次へ進む
  - 右上の「サメ選択 →」は削除するか、小さい文字リンクに格下げ
- **サメ選択**：右下（サメ一覧の下）に大きなカチンコ型の「ACTION!」ボタン。押せることがわかる控えめな動き（脈動やカチンコが鳴る）を付ける。
  **Enter でも開始**でき、ボタンにキー表示を添える。NAME 欄は ACTION の直上に置き、「名前 → 押す」を一本の流れにする。
- 未解放サメの「????」が何枠も並ぶのをやめ、1枠にまとめて「あと N 種類」と出す。
- **全画面のルール**：進む＝大きい・塗り・右下。戻る＝小さい・白か枠のみ・左上。見出し（「ロケ地を選ぶ」等）は
  ボタンと同じ黄色の箱をやめ、ボタンと見分けられるようにする。
- スマホ横（844×390）でも主ボタンがスクロールなしで見えること。

### #3 [P0] 開始直後に理不尽に死なない
- 湧き直後の無敵（`sim.js` の `iframe: 3`）は既にあり、壁にも効く。それでも **多摩川で開始数秒〜10秒ほどで「外壁に接触」で死んだ**事例がある。
  まず再現し、原因（流れに押されて無敵が切れた直後に壁へ当たる、湧き位置が壁際、等）を特定してから直す。
- 出現位置は壁から十分離す。多摩川は流れの無い帯（河川敷）に出す。
- 開始時はカメラを自機に寄せ（数秒かけて通常の倍率へ）、自機の周りに「あなたはここ」とわかる目印を出す。
  ただし既存の「自機の輪は盾の輪だけにする」方針（`game.js` drawEnvFront のコメント）と紛らわしくならない表現にする。
- **関連する不具合の調査**：多摩川のプレイ中、HUD の TIME が 0:00 のまま進まず、リザルトの生存時間も 0:00 だった。
  調布飛行場では正しく進んでいた。原因を調べて直す。
- sim.js を変える場合は `src/sim.test.mjs` にテストを足す。

## B. 手応え（ジュース）

### #4 [P0] 食べる・倒すの気持ちよさ
- 既存：`audio.js` の `sfx.eat()` は連鎖で音程が上がる仕組みがある。これを活かす。
- 餌を食べたとき：小さく弾けるパーティクル、HUD の SIZE の数字を一瞬大きく跳ねさせる。
- 相手を倒したとき：ヒットストップ（約50ms）、既存の画面揺れの調整、「○○を撮影終了！」のキルフィード表示。
- 連続で食べているときにコンボ数を表示（音の連鎖と同じ判定にそろえる）。
- 演出はすべてブラウザ側だけで完結させる（sim.js とサーバに手を入れない）。
- 引きの絵（zoom が小さいとき）でも描画負荷が増えすぎないこと。パーティクル数に上限を持つ。

### #5 [P1] すぐ手が届く目標
- ランキング表示を小さくする（いまは画面右上の4分の1近くを占めている）。上位3人＋自分、程度に。
- 「あと N で X 位」を自分の行に出す。
- 1位のサメに王冠を付ける。王冠の相手を倒したらボーナス（ボーナスを入れる場合は sim.js の変更になるので、
  まず見た目だけ入れて、ボーナスは「要判断」に挙げる）。

## C. 見た目：「水没した調布」

世界観の軸：**調布が海に沈んでいて、水の底に街や地形が見える**。破線やただの帯で範囲を示すのをやめ、
地形そのものを描いて「場所」に見せる。既存の `setLineDash` による範囲表示は原則なくす。
描画はすべて `game.js` 側。sim.js の効き（数値）は変えない。既存コメントにある描画負荷の工夫（view で切る、
グラデーションやパターンのキャッシュ）を守ること。

### #6 [P0] 調布飛行場：滑走路と飛行機の影
- 水底にアスファルトの滑走路を描く（凪の間もはっきり見える）。両端に白い「ピアノの鍵盤」型マーキングと滑走路番号。
  番号は定数にして差し替えやすくする（実際の番号は人間に確認：「要判断」に挙げる）。
- 気流が吹く数秒前から、進入灯が滑走路に沿って順に点滅して予告する。
- 吹いている間、**プロペラ機の大きな影が滑走路に沿って画面を横切る**。これが発表の目玉。
- 黄色の破線と矢羽根は、なくすか大幅に控えめにする。気流の向きは影の進む向きと、巻き上がる泡・餌の動きで伝える。

### #7 [P0] 多摩川：川らしさ
- 帯ごとに水の色を変える：河川敷＝浅瀬の明るい色、流れ＝中間、急流＝濃い青緑。境目は既存どおり溶かす。
- いまの白い斜線は雨に見えるので、**流れに乗って実際に動く漂流物（落ち葉・泡）**に置き換える。流速は物の速さで伝える。
- 急流の帯には白波（泡）、川底に石。
- 余力があれば、京王線の鉄橋の影が川を横切る。

### #8 [P1] 深大寺：湧水
- 破線の円をやめ、石組みの縁と苔、広がる波紋で湧水を描く。
- 「今もらえる／再装填中」の2状態は残す（既存コメント参照：区別がないと故障に見える）。
  もらえる＝泡と波紋が湧いている、再装填中＝水面が静か、で表す。

### #9 [P2] 各マップの水底
- 全マップ共通の「無地の水＋ドット」をやめ、マップごとに水底の地面（街区、道、森など）をうっすら描く。
  パターン1枚のタイル敷きなど、描画回数が増えない方法で。
- つつじヶ丘・仙川には環境ギミックが無い（data.js に gimmick 定義なし）。ギミック追加は今回はやらず、見た目だけ。

## D. 安定性

### #10 [P0] 会場で一斉に入られても落ちない
- 発表では会場の人にQRから一斉参加してもらう可能性がある。サーバは t3.micro。
- `server/index.mjs`：総部屋数の上限、IP ごとの同時接続数の上限、`maxPayload` を数KBへ、操作メッセージの受信頻度の上限。
  上限を超えたときは接続を断るか、既存の部屋へ寄せる。上限値は環境変数で変えられるようにする。
- `server/relay.test.mjs` にテストを足す。
- 余力があれば `scripts/loadtest.mjs` で 40人程度を流し、結果を STATUS.md に残す（発表スライドに使える）。

### #11 [P2] リポジトリ整理
- ルートにある `hash-lab.html`、`rope-probe.html`、`stitch_samezario_chofu_cinema_action/` を `tools/` などにまとめる。
  README と dev サーバからの参照が切れないこと。
