# #7 [P0] 多摩川：川らしさ（帯の水色・漂流物・白波・川底の石）

**触るファイル**: `src/game.js` のみ
**触らない**: `src/sim.js`（帯の流速・`windAt`）/ `src/data.js` / `src/main.js` / `index.html` / `src/style.css` / `server/index.mjs`

## 目的

多摩川が「雨の降る海」ではなく「流れる川」に見える。流れの速さが、流れていく物の速さでそのまま分かる。あわせて、多摩川の描画を軽くする（#3a の調査で、TIME が 0:00 のまま進まない不具合は多摩川の描画が重く fps が落ちたことが最有力の原因だった）。

## 実装方針

### 守ること（既存コメントの判断）
- **流速は sim.js の値から出す**。帯の色も物の速さも `gim.currentSpeedAt(y)` / `gim.bands`（L289〜292、L619〜620）から。数値を game.js に書き写さない（L613〜615「絵と盤面が食い違うことはない」）。
- **帯の境目は溶かす**。帯ごとに矩形を敷くと境目に無着色の継ぎ目が出る（L622〜624）。今と同じく、流速を 25 段に引いた**1本の縦グラデーション**を初回に1回だけ作る（L626〜630「毎フレーム作り直していたころは…捨てていた」）。透明側は `hexA` で同じ色のアルファ0（L27〜30）。
- **見えている範囲だけ描く**。エリアは 10536×5453px あるので、全面へ撒くと引きの絵で毎フレーム数千個になる（L643〜644、L667〜670）。漂流物も白波も `view` と帯の重なり（今の `box`）の中だけ。
- **パターンはワールド原点に敷く**（L671）。石のタイルも同じ。

### 帯ごとの水の色
- グラデーションの色を、流速 0 → 最大の順に「浅瀬の明るい青緑 → 中間 → 濃い青緑」へ補間する（不透明度を上げて、ベースの `map.water` の上にはっきり乗せる）。例: 河川敷 `#5fb7ad`、流れ `#2f8a8f`、急流 `#18575f`（要判断：色味）。
- 1本のグラデーションを `fillRect(bb)` で1回塗るのは今と同じ（`drawEnvBack` が `clip(outline)` 済み）。

### 漂流物（白い斜線の置き換え）
- 今の `streaks()` は流れの向きの短い線分の格子で、「雨に見える」。これを、**同じ格子・同じ流し方**（`flowBox` L536 で流れの座標系へ移し、u に `t * speed` を足すだけ —— 粒が1本ずつ巻き戻らない利点 L577〜580 を引き継ぐ）のまま、線分の代わりに**物を置く**。
  - 落ち葉: 小さな楕円（緑〜黄土）。格子の添字から作る種でゆっくり回す（`frac(Math.sin(...))`、L24〜25 の `frac` と同じ「乱数を持たない」作り）。
  - 泡: 白の小さな丸（2〜3個の塊）。
- 速さ = その帯の流速そのもの（world px/s）。急流ほど速く流れていく。河川敷（速度 0）には漂流物を置かない（＝止まった浅瀬）。
- 描画は**種類ごとに Path2D を1本**（`ellipse` / `arc` を積む）にまとめて fill 1回。今の `streaks` と同じく1本の Path なので、個数が stroke/fill の回数に響かない。上限 `cap` は今と同じ考え方で 1帯 600 個程度。

### 白波（急流の帯）
- 急流（`strength > 0.7`、今の L661 と同じ条件）だけ、流れに直交する短い白い弧を、漂流物と格子をずらして置く。Path2D 1本。

### 川底の石
- `stoneTile()`: 128px 程度のタイルに丸い石を数個（`gravelTile` L77 と同じ作り）。流れ・急流の帯の下に、`fillStyle = pattern` で `box` の範囲だけ1回塗る。河川敷は今の砂利をやめて、浅瀬の明るい水色＋薄い石でもよい（要判断）。
- タイルは水面の模様と見分けがつく大きさにする（水のドット 60px、`dotTile` L66）。

### 京王線の鉄橋の影（余力があれば）
- 川を南北に横切る、暗い半透明の帯1本＋橋脚の矩形数個。位置は外接矩形の u（0..1）で定数に持つ。静的なので Path2D を1回作ってキャッシュ。

### 描画の重さを測る
- 改修前後で、**同じ条件**（例: playwright で 844×390・`isMobile`・CPU 4倍絞り、または実機）で多摩川の fps を測り、改修後が改修前以上であること。参考値（#3a の調査、headless・4倍絞り）: chofu 19fps / airport 10〜12 / tamagawa 9〜10。

## 受け入れ条件

- [ ] 河川敷・流れ・急流の3帯で水の色がはっきり違い、境目に継ぎ目（色の段・透明の筋）が無い。
- [ ] 白い斜線が無くなり、落ち葉と泡が流れに乗って動く。急流ほど速く、河川敷では何も流れていない。
- [ ] 漂流物の速さが流速と一致している（急流の帯で、漂流物と同じ向きに泳がず止まっている自機の横を、漂流物が約 110px/s で流れていく）。
- [ ] 急流の帯に白波、流れ・急流の川底に石が見える。
- [ ] 漂流物・白波の位置は時刻 t と格子の添字だけで決まる（`Math.random` を使っていない）。
- [ ] 引きの絵（質量 3000 以上・zoom 最小）でも、1フレームの `drawCurrent` の fill/stroke 回数が改修前以下（Path2D をまとめていること）。
- [ ] 同じ条件で測った多摩川の fps が改修前以上。
- [ ] ミニマップの帯（`drawMini` L1056〜1071）は今のまま、または同じ色味に合わせて変える。

## リスク

- **sim.js 同期**: 触らない。絵は `t`（`draw` の引数）だけで決まる。
- **描画負荷**: 本 issue の主題のひとつ。漂流物を `drawImage` で1個ずつ描くと、引きの絵で数百回になって今より重くなる。**Path2D にまとめて種類ごとに1回**を守ること。グラデーション・タイルはキャッシュ。
- **スマホ横**: 844×390 は zoom が `fit` で下がるので、漂流物の大きさは画面 px の下限を持たせる（`drawSprings` の泡が `4.5 / cam.zoom` を下限にしている L797〜801 と同じ）。
- **衝突**: game.js の中で #3a/#3b/#4/#5/#6/#8/#9 と同居。`drawCurrent` は多摩川専用で他の issue は触らない。#9（全マップの水底）と「川底の石」が重なるので、**多摩川の水底は #7 が持ち、#9 は多摩川に手を出さない**と決めておく。

## 要判断

1. 3帯の水色（浅瀬・中間・濃い青緑）の具体的な色。
2. 河川敷を「浅瀬（水）」として描くか、今の「砂利（水ではない）」を残すか。`stage_design_plan.md` §3 ④ は河川敷を「流れの無い帯」とし、issue は「浅瀬の明るい色」と書いている。
3. 京王線の鉄橋を入れるか（余力枠）。入れるなら位置。
