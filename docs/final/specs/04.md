## 実装方針

### 1. 餌を食べたとき
- 粒: 今の `burst(e.x, e.y, e.hue, e.kind ? 8 : 3, 60)`（L321）を、自分が食べた分だけ一回り大きく（数 5〜6・速さ 90）。他人の分は今のまま。
- **パーティクル上限**: `MAX_FX = 300` を定数で持ち、`burst()` は上限を超える分を捨てる。さらに `n = ceil(n * clamp(cam.zoom, 0.4, 1))` で、引きの絵（zoom 0.34 まで下がる、L438）ほど粒を減らす —— 引くと粒は点にしか見えないので、数を減らしても絵は変わらない。今は上限が無く、ボス撃破（L363〜364 で 100粒）と死亡の連鎖が重なると数百粒になる。
- `fx.splice(i, 1)`（L423）は上限 300 なら許容。気になるなら末尾と入れ替えて pop。
- SIZE の跳ね: `paintHud` で前回の `mass` より増えていたら `#hud-mass` に `bump` クラスを付け直す（`classList.remove` → `void offsetWidth` → `add`。`main.js` の `clap()` L1016〜1025 と同じ手口）。間隔は 150ms 以上空ける（HUD は 0.08秒ごと、L1120）。

### 2. コンボ
- 判定は `audio.js` の連鎖と同じ: 前回から `EAT_GAP`（500ms）以内に次を食べたら +1、空いたら 1 から。`EAT_GAP` を import して使う（値を二重に書かない）。
- 「自分が食べた」の判定は `'eat'` の音と同じ条件（L327〜328: `s === player || d2 < mouth²`）。オンラインでは誰が食べたかが来ない（`applySnapshot` は `shark: null` で積む、L1247）ので、音と同じ肩代わりをそのまま使う。
- 表示: 3連以上で SIZE の横に「×N COMBO」。途切れたら 0.4秒でフェード。

### 3. 相手を倒したとき
- **自分が倒したかの判定**: `'die'` イベントは倒した相手を持っていない（`sim.js` の `die()` L687 は `{ k, shark, cause }` だけ）。sim.js は触らない約束なので、`cause` が `` `${player.name} の胴体` `` か `` `${player.name} の泳いだ跡` `` に一致するかで判定する（オフラインは `sim.js` の文字列、オンラインはスナップショットの `d`（死因、L1200）がそのまま来る）。
  - **既存の不具合も一緒に直る**: オンラインでは `player.kills` がサーバから届かない（`packShark` L1175 に `kills` が無く、`resolve` も回らない）ので、**リザルトの撃破数がオンラインでは常に 0**。上の判定で数えた値を `endRun` の `kills`（L287）に使う（`net` があるときだけ。オフラインは従来の `player.kills`）。
  - 名前が他の参加者と同じだと誤判定する。オンラインの名前は利用者が付ける10文字なので重複はまれ。正確にしたいなら sim.js の `deaths` に倒した側の nid を載せる（要判断）。
- **ヒットストップ**: 自分が倒した瞬間に `hitstop = 0.05`。`frame()` で `hitstop > 0` の間は `step()` を呼ばず、`draw()` と `net.send` は続ける。止まるのは手元の予測だけで、サーバは止まらない（50ms はスナップショットの d < 25 のデッドゾーン、`applySnapshot` L1285 に収まる）。
- **揺れの調整**: 今は**盤面のどこで誰が死んでも** `cam.shake = 8`（L347）。画面外の遠い死でも揺れる。→ `spatial()`（L301）の `vol` を掛けて `8 * vol`、画面外（vol が小さい）なら揺らさない。自分が倒したときは 14、自分が死んだときは今の 26 のまま。
- **キルフィード**: 「○○を撮影終了！」を上中央に最大3行、2.5秒で消える。`onHud` に `feed: [名前...]`（前回の HUD 以降に倒した分）を載せ、`main.js` が DOM に積む。名前は `esc()` を通す（オンラインの名前は利用者入力）。他人同士のキルは出さない（要判断）。

### 4. 全部ブラウザ側で
- sim.js・サーバには一切手を入れない。`events` を拾って絵と音にする今の分担（`game.js` L308〜312 のコメント）に乗る。

## 受け入れ条件

- [ ] 自分が餌を食べると粒が弾け、左上の SIZE の数字が一瞬大きく跳ねる。
- [ ] 続けて食べると「×3 COMBO」…と数が増え、0.5秒空くと途切れる。音の高さの上がり方と数の増え方がそろっている。
- [ ] ボットを自分の胴体に当てて倒すと、一瞬（約50ms）止まり、画面が揺れ、上中央に「（名前）を撮影終了！」が出て 2.5秒で消える。
- [ ] 画面外で他のサメが死んでも画面が揺れない。
- [ ] **オンライン**でボットを倒すと、リザルトの撃破数が 1 以上になる（改修前は常に 0）。
- [ ] パーティクルは同時に 300 を超えない（`window.__sz` に `fx` を足して確認するか、`burst` に一時ログ）。
- [ ] 育ちきった引きの絵（質量 3000 以上）で、改修前と比べて fps が落ちていない（DevTools Performance、同じ端末・同じマップで比較）。
- [ ] `prefers-reduced-motion: reduce` で SIZE の跳ねとフィードの動きが止まる（表示自体は出る）。
- [ ] `npm test` が通る（sim.js 不変なので既存テストのまま）。

## リスク

- **sim.js 同期**: 触らない。ヒットストップは手元の予測を 50ms 止めるだけで、`applySnapshot` は止めない。
- **描画負荷**: 粒の上限と zoom による間引きで、今より重くならない（今は上限が無い）。
- **スマホ横**: キルフィードを上中央に置くと、横画面では左上の SIZE・右上の順位帯の間（約 300px 幅）に入る。1行の長さを `max-w` で切る。深大寺のボス HP 板は横画面では左下（`style.css` の `#hud-boss`）なので重ならないが、PC では上中央（`index.html` L530）で**重なる** → フィードはボス板の下に出す。
- **衝突**: `frame()` は #3a（dt の刻み回し）と #5（順位表）も触る → #3a → #4 → #5 の直列。`paintHud` と `#hud` は #5 も触る → 同上。`draw()` のパーティクル部分は #3b・#5・#6・#9 と近いが別の行。

## 要判断

3. コンボを何連から出すか（推奨 3）。
