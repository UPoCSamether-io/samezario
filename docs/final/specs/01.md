# #1 [P0] 即リトライと「すぐ遊ぶ」

**触るファイル**: `src/main.js` / `index.html` / `src/style.css` / `src/progress.js`（既定値に1項目足すだけ）

## 目的

死んでから次のプレイまでを「キー1つ」にする。2回目以降は、タイトルから1クリックで前回と同じ撮影に入れる。

## 実装方針

### リザルトでの Space / Enter
- `addEventListener('keydown', ...)` を1本足し、`cur === 'result'` のときだけ `play()` を呼ぶ（`#retry` と同じ道。`play()` の `starting` ガードがそのまま連打よけになる）。
- **誤爆よけ（必須）**
  - Space はゲーム中のダッシュキー（`game.js` onKey L203）。押したまま死ぬとオートリピートでリザルト直後に即リトライしてしまう → `e.repeat` を無視し、さらに `showResult` から **400ms 以内**の入力は捨てる。
  - Enter は、Tab でフォーカスが「ロケ地を変える」等に乗っているとそのボタンの click と二重に走る → `e.target.closest('button, input, a')` が `#retry` 以外なら何もしない。
  - `e.preventDefault()` してページのスクロールを止める。
- キー表示は既存の `.kbd-badge`（`style.css` L770 で `pointer: coarse` では自動で隠れる）を使う。

### タイトルの「前回の設定ですぐ遊ぶ」
- 出す条件: `save.map` があり、そのマップが `isUnlocked`、かつ `save.shark` が `isUnlockedShark`。初回（`save.map` 空）は出さない。条件を満たさなければ黙って隠す（解放状態は史料の獲得などで変わる）。
- 押したら: `selMap` / `selShark` を前回の値にし、`nameInput.value = save.name` のまま `play()`。`play()` は `show('game')` を自分で呼ぶので、ロケ地・サメ選択を経由しない。
- **置き方は nav を4段にしない**。`index.html` の史料ボタンのコメント（`index.html` L126「4つ目に足すと nav が潰れる」）と、横画面タイトル（`style.css` L940〜、縦 390px に収める組み替え）が根拠。
  案: 先頭の「ゲームスタート」を**同じ高さの分割ボタン**にする —— 左の大きい側「▶ すぐ遊ぶ（多摩川／映画サメ）」、右の細い側「選ぶ」（= 従来の `data-go="map"`）。前回が無いときは今までどおり1枚の「ゲームスタート」。
- 「ゲームスタート」の `data-go="map"` は残す（初回の遊び方の寄り道 L445 と `scripts/shots.mjs` の `toMap()` がこのセレクタ `#s-title [data-go="map"]` を使う）。

### 「1秒以内・1操作」の測り方
`endRun` は撃破の絵を見せるために 900ms 待ってからリザルトへ抜ける（`game.js` L291 のコメント）。これは残す。
目標は「**リザルトでキーを押してから、次のゲーム画面の rAF が回り始めるまで 1秒以内**」と読む。内訳は `connect()`（hello の往復）＋ `show()` の CLAP 110ms + SHUT 190ms。

## 受け入れ条件

- [ ] リザルトで Space を押すと `#retry` と同じく同じロケ地・同じサメで次のゲームが始まる。Enter でも同じ。
- [ ] Space を押しっぱなしで死んでも、リザルトが出た瞬間に勝手に再開しない（押し直しで初めて再開）。
- [ ] リザルトで Tab で「ロケ地を変える」にフォーカス → Enter で、ロケ地選択に行く（リトライが二重に走らない）。
- [ ] `#retry` の右上に「SPACE」の小さいキー表示。タッチ端末（`pointer: coarse`）では出ない。
- [ ] 一度も遊んでいないセーブ（`samezario.save` を消した状態）ではタイトルに「すぐ遊ぶ」が出ない。
- [ ] 多摩川で1回遊んでタイトルへ戻ると「すぐ遊ぶ（多摩川／○○サメ）」が出て、1クリックでゲームが始まる。HUD の SCENE が多摩川。
- [ ] リロード後も「すぐ遊ぶ」が残る（localStorage に `map` が入っている）。
- [ ] ローカル（dev サーバ相乗りの /ws あり）で、リザルトでキーを押してから次の盤面が動き出すまで 1秒以内（DevTools の Performance か `performance.now()` のログで確認）。
- [ ] 844×390 のタイトルで、分割ボタンを含む nav がスクロールなしで全部見える。
- [ ] `npm test` が通る（`progress.test.mjs` に `map` の既定値の確認を1つ足す）。

## スクショで確認する画面（`scripts/shots.mjs`）

- `01-title-pc` / `01-title-sp`（初回セーブなので「すぐ遊ぶ」は**出ない**のが正）
- `17-result-pc` / `17-result-sp`（SPACE バッジ）
- 「すぐ遊ぶ」が出る状態は shots に無い。必要なら `SAVES.all` に `map: 'tamagawa'` を足した別画面を #0 担当に依頼（要判断ではなく作業依頼）。

## リスク

- **sim.js 同期**: なし。
- **描画負荷**: なし。
- **スマホ横**: タイトル nav の縦が増えると 390px を超える。分割ボタンで高さを変えないこと。
- **サーバ不在時**: `connect()` はサーバが無いと最大 2.5秒待つ（`net.js` L35）。会場で WS が詰まると「1秒以内」は崩れる。ここは #10 の範囲。
- **衝突**: #2a/#2b と `index.html` / `main.js` / `style.css` を共有（ロケ地・サメ選択の主ボタンと「全画面のルール」）。#1 → #2 の順に直列。

## 要判断

1. 「すぐ遊ぶ」の置き方 —— 分割ボタン（推奨）／「ゲームスタート」の下に小さな文字リンク／ゲームスタートそのものを「すぐ遊ぶ」に置き換えて「選び直す」を小さく。
2. 「1秒以内」をどこから測るか —— 上記（キーを押してから）で良いか。死亡からの 900ms（撃破の絵を見せる時間）も削るか。
