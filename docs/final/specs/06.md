## 目的

## 実装方針

### 前提（sim.js から読むだけ）
- 滑走路は `gim.runway = { x0, y0, x1, y1, len, w, ux, uy, ang }`（`sim.js` L226〜229）。`w` は帯の**半幅 340px**（`data.js` の `width`）。気流は `x0,y0 → x1,y1` の向き（`ux, uy`）に押す（`windAt` L284〜285）。
- 効きは中心で最大、縁で 0 の直線（`nearRunway` の `k = 1 - d / w`、L255）。
- 周期は `def.period = 9`、吹くのは `def.dur = 2.6` 秒、強さは `gim.level(envT)`（sin で丸めた 0..1）。時計は `world.envT`（スナップショットで同期、`stage_design_plan.md` §4.5）。**演出もすべて `world.envT` から出す**（`Math.random` や `performance.now` を混ぜると端末ごとに絵が割れる —— `drawSprings` の泡が「絵は t だけで決まる」L783 としているのと同じ）。

### 滑走路（凪の間もはっきり見える）
- `ctx.translate(x0, y0); ctx.rotate(ang)` の座標系（今の `drawGust` と同じ）で描く。
- **舗装**: 幅 `w * 0.55 * 2` の暗いアスファルト色の矩形（不透明度 0.55 程度。水の中なので少し沈ませる）。
- **路肩→水**: 舗装の外から `w` まで、`createLinearGradient` で透明へ落とす。効きが縁で 0 になる直線（`k`）と、見た目の濃さの落ち方をそろえる＝「濃い所ほど強く押される」が絵で読める。グラデーションは静的なので初回に1回だけ作ってキャッシュ（`drawCurrent` の `tint` L610〜637 と同じやり方）。
- **センターライン**: 白の短い実線の列（Path2D 1本にまとめて stroke 1回）。`setLineDash` は使わない（issue C の方針）。
- **ピアノの鍵盤**: 両端に白い縦縞 8〜12本（Path2D 1本で fill 1回）。
- **滑走路番号**: 両端の鍵盤の内側に `RUNWAY_NUMBERS[0]` / `[1]` を `fillText`。番号は進入方向から読めるよう、片側は 180° 回して描く。フォントは既存の `"Space Grotesk"`。
- 引きの絵（zoom 0.34）でも舗装と番号が読める大きさにする（番号の文字高 ≈ 舗装幅の 0.6）。

### 進入灯（予告）
- 位相 `ph = envT - floor(envT / period) * period`（`level` L245 と同じ畳み方。二重剰余は端が内側へ落ちるとコメントにあるので floor 版を使う）。
- `period - GUST_WARN <= ph < period` の間、**風上側の端（x0,y0）から風下へ**、滑走路に沿って並べた灯火（10〜14個の点）が順に光る（流れる灯＝シーケンスフラッシャ）。光る位置は `(ph - (period - GUST_WARN)) / GUST_WARN` と灯の添字から決める。
- 吹いている間（`lv > 0`）は全灯が弱く点きっぱなし。

### プロペラ機の影（目玉）
- 吹いている間（`0 <= ph < dur`）だけ、影が `x0,y0` の手前から `x1,y1` の先まで、`ph / dur` に比例した位置を通過する（＝気流の向きと同じ向きに動く）。滑走路長 3570px を 2.6秒で抜けるので約 1400px/s —— 押される速さ（205px/s）よりはるかに速く、「頭上を飛んでいった」感じになる。
- 形: 双発または単発プロペラ機の上面シルエット（主翼・胴・尾翼）を Path2D でモジュール読み込み時に1回だけ作る。翼幅はワールド 900〜1200px（画面1枚分前後）。
- 色: `rgba(16, 31, 35, 0.28)` 程度の暗い半透明。**サメと餌より上**に描き、外周の外にははみ出さない（`ctx.clip(outline)`）。水面に落ちた影なので、サメの上にも落ちるのが自然。
- 影の位置が `view` と重ならなければ描かない（外接円で判定）。
- （任意）通過の瞬間に `sfx` の低い風切り音 —— `audio.js` を触るので別 issue 扱い。

### 破線と矢羽根
- 帯の縁の黄色い破線（L704〜711）とセンターの破線（L712〜719）は撤去。
- 矢羽根（L722〜743 の `chevrons`）は撤去し、代わりに**巻き上がる泡**: 吹いている間だけ、帯の中から白い小さな丸が気流の向きへ流れながら消える。位置は添字と `envT` だけから作る（`drawSprings` の泡 L785〜803 と同じ作り）。数は 40〜60 個・Path2D にまとめて fill 1回。
- 餌が渦に巻かれる動き（`swirlFood`、sim.js 側）はそのまま残るので、向きは「影の進む向き」「泡の流れ」「餌の渦」の3つで伝わる。
- ミニマップの滑走路の帯（`drawMini` L1048〜1055）はそのまま（地図の上では「ここで吹く」が先に分かる方がいい —— L1047 のコメント）。

## 受け入れ条件

- [ ] 凪の間も、水底にアスファルトの滑走路・センターライン・両端の鍵盤・番号がはっきり見える。
- [ ] 気流の 2.5秒前から、進入灯が風上の端から風下へ順に光る。
- [ ] 吹いている 2.6秒の間に、プロペラ機の影が滑走路に沿って**気流と同じ向き**へ画面を横切る。サメの上にも影が落ちる。外周の外には出ない。
- [ ] 黄色の破線・矢羽根が無い（または大幅に控えめ）。`drawGust` に `setLineDash` が残っていない。
- [ ] 同じ部屋の2台（オンライン）で、進入灯と影のタイミングがそろう（`world.envT` だけから作っている）。
- [ ] 引きの絵（質量 3000 以上）でも滑走路が読め、fps が改修前より落ちていない（DevTools Performance で `drawGust` の時間を比較）。
- [ ] 番号は `RUNWAY_NUMBERS` 1か所を書き換えるだけで差し替わる。
- [ ] `npm test` が通る（sim.js 不変）。

## リスク

- **sim.js 同期**: 触らない。演出は `world.envT` だけから作るので、全員に同じ絵が出る。
- **描画負荷**: 追加は Path2D の fill/stroke が10回程度＋泡 1回。撤去する矢羽根（最大 700本の Path）より軽くなる見込み。グラデーションはキャッシュする（`drawCurrent` の `tint` と同じ）。#3a の調査で飛行場は chofu の約半分の fps だった（headless・CPU 4倍絞り）ので、改修前後の fps を必ず比べる。
- **スマホ横**: 844×390 は縦が狭く、影の翼幅が画面より大きくなる。影は大きくてよい（「何かが通った」が伝われば十分）が、進入灯は画面に入る長さで並べる。
- **衝突**: game.js の中で #3a/#3b/#4/#5/#7/#8/#9 と同居。`drawGust` は飛行場専用でほかの issue は触らない。`draw()` に1行足す所だけ #3b（目印）・#4（パーティクル）と近い → merge 時に注意。#9（水底）は飛行場の水底を描くので、舗装と重ならないよう #6 → #9 の順。

## 要判断

1. **滑走路番号**。調布飛行場（RJTF）の滑走路は 17/35 と理解しているが、人間が確認すること。番号の向き（ゲームの滑走路は北北西→南南東で、気流は北から南へ押す）との対応も確認。
2. 影の機種（単発／双発。調布飛行場の離島便は双発機）と大きさ。
3. 自機の周りの黄色い矢印（`drawEnvFront`）を残すか、細くするか、消すか。
4. 影をサメの上に描くか、水底（サメの下）に描くか。推奨: 上。
